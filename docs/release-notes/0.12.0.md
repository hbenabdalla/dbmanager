# DB Manager 0.12.0

**DB Manager 0.12.0** is the first public release. It manages heterogeneous relational database
fleets from one place: PostgreSQL, MySQL, MariaDB, SQL Server, Oracle and Db2. It covers
inventory, monitoring, query analysis, execution plans, security posture, evidence-based
recommendations, guarded administration, alerting and, new in this release, backup and restore.

It contains roadmap milestones 0.9 to 0.12. Each roadmap task was checked against the code and
the tests before release; the results are in the [roadmap audit](../product/roadmap-audit.md).

## Highlights

### Backup & restore

- **Platform backups.** DB Manager backs up its own configuration: inventory, identity and RBAC,
  findings, alerting, settings and backup configuration, plus the audit log and telemetry if you
  choose.
  - Archives are versioned and encrypted with [age](https://age-encryption.org).
  - They are stored on local disk, a mounted volume or NFS share, or an S3-compatible bucket.
  - A backup is marked successful only after the stored copy has been read back and verified.
- **Restore wizard.** Before anything changes, the wizard checks integrity and compatibility,
  then shows the exact impact from a trial run that is rolled back. You confirm by typing a
  phrase, a safety backup is taken first, and the result is validated afterwards.
- **Managed-database backups.** Each engine uses its own tooling:
  - PostgreSQL: `pg_dump` / `pg_restore`.
  - MySQL and MariaDB: `mysqldump` / `mariadb-dump`.
  - SQL Server: native `BACKUP` / `RESTORE`.
  - Oracle: Data Pump.
  - Db2 LUW: online `BACKUP`.

  Restores always go into a new database. DB Manager never overwrites an existing one.
- **Policies.**
  - Schedules: daily, weekly or monthly, in your time zone.
  - Retention: keep the last N backups, the last N days, or daily, weekly and monthly generations.
  - Bulk runs by environment, site or tag, with progress for each database.
  - Notifications on failure, Prometheus metrics, and a "Protected / Not protected" status on each server.
- **Disaster recovery.** To rebuild an installation, point a fresh install at the storage
  target, scan it, verify the backups and restore.

### Alerting

- **Rules.** Scope rules by tag and evaluate them over a time window (average, minimum or maximum).
- **Alert handling.**
  - An alert inbox where you acknowledge, comment on and resolve alerts.
  - Re-notification until an alert is acknowledged.
  - Recurring maintenance windows that follow daylight saving time.
- **Notifications.**
  - Slack and Microsoft Teams presets.
  - SMTP over STARTTLS or implicit TLS.
  - Delivery retries with backoff.
  - Routing by environment, tag and engine.

### Enterprise integration

- **Sign-in security.** Local accounts can use multi-factor authentication (TOTP with recovery
  codes) under an enrollment policy. OIDC providers can require MFA through the `amr` / `acr` claims.
- **SIEM forwarding.** The audit log can be forwarded to a SIEM as syslog (RFC 5424, over UDP, TCP or TLS) or as signed webhooks.
- **Vault credentials.** Database passwords can live in HashiCorp Vault.
- **Automation.** API tokens and rate limiting.
- **LDAP.** Validated against a real OpenLDAP server.

### Operations

- Redacted diagnostic bundles for each server.
- New pages to manage environments, sites, clusters and applications.
- A restore drill and upgrade-with-data migration tests run in CI.

## Upgrading

This is the first release, so there is no earlier tagged version to upgrade from. Development
installations upgrade automatically: migrations `0007` to `0010` run when the backend starts.
Before upgrading, back up with `scripts/backup.sh`, and keep `DBM_MASTER_KEY`.

If you used `DBM_SMTP_STARTTLS`, set `DBM_SMTP_SECURITY` instead. The old variable still works.

## Known limitations

- **Real-engine validation of backups.** Backups were validated on PostgreSQL 16 and MariaDB 10.11.
  The SQL Server, Oracle, Db2 LUW and MySQL backup providers ship with integration tests that
  still need a run in the Docker integration environment. The same is true for the Keycloak (OIDC) and Vault tests.
- **No point-in-time recovery.** Db2 LUW restores and Oracle RMAN backups are done with external
  tools; for Db2 LUW, DB Manager shows the restore command to run.
- **Db2 for z/OS backups** are not run by DB Manager.
- **Storage targets.** Azure Blob and Google Cloud Storage aren't supported natively yet;
  S3-compatible endpoints work. Cloud secret managers are planned.
- **Reports** export CSV only and can't be scheduled yet.
- **Kubernetes.** There is no Helm chart yet, and the manifests aren't validated in CI.

The full list of changes is in the [changelog](https://github.com/hbenabdalla/dbmanager/blob/main/CHANGELOG.md).
